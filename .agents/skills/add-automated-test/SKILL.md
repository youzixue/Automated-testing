# 多端自动化测试开发

遵循仓库根目录 `AGENTS.md`；本文提到的代码路径均相对仓库根目录。

## 按平台读取

只读取本次涉及的平台；跨端共享流程变更读取所有受影响分支。

- API：[接口测试指南](references/api.md)。
- Web：[浏览器测试指南](references/web.md)。
- App、小程序、公众号：[设备与微信测试指南](references/mobile-wechat.md)。

## 开发流程

1. 明确入口、前置条件、输入、可观察结果及结束边界。区分创建订单、拉起支付页和完成支付。
2. 从相邻用例向下追踪 fixture、业务对象、配置和数据来源，复用当前实际调用的实现。
3. 按需求设计正常、异常和边界场景；每个场景说明独立预期，避免只断言“未抛异常”。
4. 将重复交互封装进现有页面、服务或屏幕对象；用例负责场景编排和结果断言。没有复用需求时不增加框架层。
5. 按当前 YAML 与 pytest 参数化方式组织数据，保持参数 ID 可读；使用共享数据时检查是否发生原地修改和跨用例污染。
6. 使用 `pyproject.toml` 中已注册的 marker，沿用相邻用例的 Allure feature、story、title 和 step。新增 marker 时同步注册。
7. 选择单个用例或相关目录验证，明确所需目标、凭据和设备。新增场景应能因错误结果而失败，不能靠宽泛捕获或跳过变绿。

## 交付

列出场景、涉及文件、预期断言及实际验证结果。缺少选择器、接口约定或设备证据时明确未验证部分，不编造可用接口或已经跑通的结论。

# 测试失败排查

遵循根目录 `AGENTS.md`，下列路径相对仓库根目录。

## 先定位失败阶段

1. 获取实际命令、工作目录、平台、环境选择、失败 node ID 和首个有效异常。读取现有日志或 Allure 附件，不先重跑全部测试。
2. 区分收集失败、fixture setup 失败、业务步骤/断言失败和 teardown 失败。先处理导致后续错误的首个原因。
3. 检查输入和环境时只确认变量是否存在、来源及类型，不输出密码、密钥或完整配置。
4. 按下表追踪实际调用，形成可验证假设；用户曾运行成功是重要背景，不是当前环境结果的替代。

## 按平台取证

| 分支 | 重点检查 |
|---|---|
| 收集/依赖 | `pyproject.toml`、README 额外安装步骤、完整 import 异常；根 fixture 对可选依赖的处理不代表平台模块也能缺依赖加载 |
| 配置/fixture | `tests/conftest.py`、平台 `conftest.py`、`src/utils/config/manager.py`；追踪环境选择、dotenv 加载时机、缓存、YAML 合并与用例覆盖顺序 |
| API | `src/api/services/payment_service.py`、模型和 YAML；区分请求未发出、HTTP 错误、解析错误及业务状态失败；检查签名输入、订单重复和共享数据污染 |
| Web | `tests/web/conftest.py`、用例实际 import 的页面对象；检查异步调用、定位器、当前 URL、截图和错误提示；区分 OCR 与业务错误 |
| App | `tests/mobile/conftest.py`、屏幕对象；检查设备授权、URI、应用状态、Poco 连接及模板匹配 |
| 小程序/公众号 | `tests/wechat/conftest.py`、`src/wechat/utils/navigation.py` 和公众号入口；确认目标名称、入口路径、当前 WebView 页面和截图 |
| 跨设备端流程 | `src/common/components/monthly_card_flow.py`；区分入口差异与共享步骤错误，核对 Activity 断言平台和支付结束边界 |
| 报告/清理 | 平台 `pytest_runtest_makereport`、全局截图辅助函数、客户端/设备释放；保留最初业务异常，不让附件错误掩盖它 |

## 验证假设与修复

- 优先用已有证据或最小相关用例验证；同一设备不并发操作。
- 检查实际配置消费者，而非仅看变量模板或注释；静态疑点标为待验证，不直接当作根因。
- 下单、重复订单和登录重试可能改变目标状态。重试应针对明确假设，出现同一结果且没有新证据时停止盲目重试。
- 修复应对应已定位原因，保持业务预期；不通过删除断言、吞异常、增加无条件 skip 或大量重试掩盖失败。
- 修复共享组件后检查受影响入口；缺少设备或服务时交付静态发现及待执行命令，不宣称修复已运行验证。

## 交付证据

说明现象、根因或待验证假设、修改范围、实际命令与结果。
分别记录通过、失败、跳过和未执行；收集成功不等于业务用例通过。
